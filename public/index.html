Model card & provenance

v1.0.0

Intended use

Learning, reproducible model comparison and exploring classification policies for machine observations.

Dataset

UCI AI4I 2020 · 10,000 synthetic observations · 339 failure labels. The binary target is Machine failure.

Dataset and attribution ↗ · CC BY 4.0 · DOI 10.24432/C5HS5C

6,000 train · 2,000 validation · 2,000 test. Stratified split, seed 42.

Preprocessing and leakage controls

Numeric medians and logistic scaling are fit on training data only. Inputs include six observed features plus temperature gap, mechanical power and wear × torque. Product category uses fixed one-hot encoding. UID, Product ID and all failure-mode labels are excluded.

Model selection and imbalance

Two fixed candidates use class weighting. Validation average precision chooses the model; validation F2 chooses the threshold over 0.05–0.95 in steps of 0.01. F2 emphasizes recall. The test set is never used for that selection. No oversampling, hyperparameter search or calibration is claimed.

Limits and responsible interpretation

This benchmark encodes synthetic physical rules. A stratified random split can share operating regimes across sets. Neither field performance, remaining useful life, causal explanations nor industrial safety is validated. Missing inputs may degrade results. Models have not been calibrated; scores are not reliable real-world probabilities.

Deployment and privacy

Python trains the models offline. Numeric parameters are exported to JSON. A Node API serves matching inference on Vercel without Python runtime dependencies or a paid AI API. Application code does not persist sensor submissions. Hosting providers may retain request metadata. Saved policies remain in localStorage.

Which signals matter?

Validation permutation importance · decrease in AP.

Global, model-specific association—not a causal or per-observation explanation. Correlated inputs can mask each other's importance. Values use three seeded repeats.

Ordered-row stress check

A separately retrained model uses rows 1–6,000 for training, 6,001–8,000 for validation and the last 2,000 for testing.

Thresholds are selected on that split's validation set. Row order is only a stress proxy; no actual timestamps or independent machine IDs establish a true prospective evaluation.
